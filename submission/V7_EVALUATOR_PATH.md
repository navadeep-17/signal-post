# Signalpost V7 evaluator-path addendum

Updated: 2026-10-03

This addendum documents the recommended evaluator command for the current V7 product surface. It is additive to the certified V5 submission lineage described by `SUBMISSION.md` and `submission/manifest.json`.

## Recommended one-command evaluator path

Use `scripts/run_signalpost_v7.py` with the same evaluator arguments previously passed to `scripts/run_signalpost_v2.py`:

```bash
uv run python scripts/run_signalpost_v7.py \
  --organisations evaluator-100.jsonl \
  --bulk brreg-enheter.csv \
  --output out/final-output.jsonl \
  --report out/final-report.json \
  --product-output out/signalpost.html \
  --work-dir out/final-work \
  --run-id builderr-eval-v7-001 \
  --expected-count 100 \
  --workers 8 \
  --site-timeout 6 \
  --wikidata-timeout 8 \
  --max-challenge-requests 2000 \
  --max-third-party-cost-usd 0 \
  --max-wall-runtime-seconds 2400 \
  --annual-workforce-workers 4 \
  --annual-workforce-timeout 60 \
  --annual-workforce-min-start-interval 2.1 \
  --annual-workforce-ocr-pages 8 \
  --annual-workforce-ocr-dpi 110
```

## What the V7 wrapper changes

The wrapper does not replace or modify the certified V5 evaluator/data runner. It performs two sequential steps:

1. runs `scripts/run_signalpost_v2.py` with the original evaluator arguments unchanged;
2. only after that succeeds, runs `scripts/build_v6_ui.py` against the emitted final JSONL and writes the hardened V6 evidence workspace to the same `--product-output` path.

If the V5 runner fails, the V6 build is not attempted. The V6 build is deterministic, local, and adds no network requests or third-party API cost.

## Current evaluator-facing workspace

The final HTML workspace generated by the V7 wrapper includes:

- global company search with exact-match priority;
- evidence-backed company profiles;
- six-question decision brief with pooled evidence links;
- explicit reporting/effective/publication date context when already present in evidence;
- descriptive company comparison with a differences-only filter;
- recent canonical change timeline;
- evidence drawer and verify-all-evidence flow;
- deterministic, evidence-bounded Ask Signalpost answers;
- explicit data-gap/unknown handling;
- careers-page discovery and grounded hiring answers that do not infer an active vacancy;
- responsive/mobile and keyboard-accessibility behavior.

Signalpost does not rank companies, infer a preferred company, or convert missing evidence into a negative claim.

## Careers-page boundary

A verified company-owned careers page is published as `hiring.careers_page`. It is a hiring surface, not an active vacancy. The UI states this explicitly when no qualified `hiring.job_posting` fact exists.

## Certified lineage remains unchanged

`submission/manifest.json` remains the machine-readable declaration of the certified V5 evidence/data lineage and pinned evaluator identities. V7 is an additive evaluator/product wrapper around that lineage. The immutable certified release data, request ceilings, source-rights declarations, and V5 smoke-test evidence are not rewritten by this addendum.

Builderr remains authoritative for the checked collection and official score. Repository tests and audits are engineering evidence only; this addendum does not claim an official score.
